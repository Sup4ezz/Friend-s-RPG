# LORGUS — правила работы с репозиторием

## Главный источник контекста

Всегда сначала прочитать:

1. `LORGUS_CHECKLIST.md` — главный мастер-файл проекта.
2. `.agent/STATE.md`
3. `.agent/TASKS.md`
4. `.agent/DECISIONS.md`
5. `.agent/CURRENT.md`

Если сведения расходятся, сначала сверить их с актуальным кодом и последними изменениями, затем привести документацию к единому состоянию.

## Обязательное правило завершения

**Ни одна работа по LORGUS не считается завершённой, пока не обновлён `LORGUS_CHECKLIST.md`.**

После каждой работы обязательно записать:
- что сделано;
- какие файлы/части проекта изменены;
- какие проверки выполнены;
- какие проблемы обнаружены;
- какие решения приняты;
- что осталось;
- точку остановки;
- следующую конкретную задачу.

Новый чат должен иметь возможность продолжить работу по ссылке на репозиторий без просьбы к пользователю пересказывать контекст.

## Работа

1. Найти текущую незавершённую задачу.
2. Изучить существующую реализацию.
3. Сделать минимально необходимое изменение.
4. Проверить затронутый код.
5. Исправить найденные безопасные ошибки.
6. Обновить мастер-чеклист и техническое состояние.
7. Только после этого считать итерацию завершённой.

## Инварианты LORGUS

- Физическое RP-присутствие — источник истины.
- Открытие карточки локации не создаёт присутствие.
- Персонаж читает/пишет только пространство, где физически находится.
- Дороги — явный неориентированный граф.
- Нельзя придумывать прямые маршруты.
- Land и sea различаются.
- Геенна закрыта игрокам и не может быть местом рождения.
- Flood не является RP и не меняет presence.
- Письма — задержанная игровая коммуникация.
- Сохранять литературный dark-fantasy стиль.
- Не превращать интерфейс в generic RPG HUD.
- Не коммитить секреты.

## Запреты

Не удалять production-данные, не ослаблять RLS, не раскрывать секреты и не делать необратимые изменения production schema без необходимости и проверки.
