# LORGUS — аудит RP presence и сообщений (2026-10-25)

## Объём проверки
Read-only аудит production Supabase проекта `dxdxnttpznoekaiecrlv` и актуальных SQL-миграций ветки `main`. Не выполнялись игровые записи, миграции, изменения прав или deploy. Browser QA не проводился.

## Подтверждённые проверки

- Production migration history содержит `20261006000100`–`20261006000400` для RP schema/presence/messages security.
- `rp_presence`: RLS включён. Для authenticated присутствуют публичное/собственное SELECT-правило и restrictive blacklist gate. Прямые INSERT/UPDATE/DELETE для authenticated отозваны; запись предназначена через RPC.
- `set_lorgus_rp_presence`: SECURITY DEFINER; anon execute=false, authenticated execute=true. В production-функции проверяются блокировка доступа, auth.uid(), approved ownership, тип/видимость, каноническая локация/концы маршрута, прямое ребро маршрута и соответствие начала дороги текущей локации.
- Переход с дороги в локацию сверяет пункт назначения с активной дорогой и считает активные road posts текущего путешествия после started_at/updated_at. Требование: 2 поста обычно, 1 при найденном маунте, 0 при разрешённом обходе дороги. Разовая награда обхода помечается used_at.
- `send_lorgus_rp_message`: SECURITY DEFINER; anon execute=false, authenticated execute=true. Проверяет approved ownership, формат сообщения и точное совпадение с текущим presence; дорожный пост требует существующую активную road-presence. Отправка с предметами делегирует проверку этой функции.
- `get_lorgus_rp_messages`: SECURITY DEFINER, authenticated execute=true. Проверяет auth, одобрение/владение выбранным персонажем и, если у персонажа уже есть presence, разрешает чтение только соответствующего RP-пространства. Прямой SELECT для игроков намеренно отсутствует; чтение идёт через character-scoped RPC. Админский SELECT-policy существует.
- Не выявлено подтверждённого обхода переходов в просмотренных функциях, который позволял бы после закрепления персонажа произвольно менять локацию без дороги/правила обхода. Это вывод по коду и конфигурации, не live browser penetration test.

## Найденные вопросы

1. **Несогласованность канонических конечных точек маршрутов (функциональный дефект, не подтверждённая уязвимость).** В серверном allowlist присутствуют локации Атэрона, Каэлора, Ксандра, Лирэна, Морвейна и «Здание Совета» в Святых Землях; для «Спорных Земель» локация отсутствует. При этом граф маршрутов содержит Святые Земли ↔ Спорные Земли и Морвейн ↔ Спорные Земли. Из-за проверки endpoint такие маршруты не могут быть полностью пройдены через обычные location/road переходы, пока не определены и не внесены канонические локации. Не расширять allowlist догадками — сначала сверить с каноном и клиентским списком локаций.
2. **Первый RP-пост фиксирует стартовую локацию.** `send_lorgus_rp_message` при отсутствии presence создаёт location presence по указанным региону/локации. Это соответствует миграции `20261006000800_rp_first_post_lock.sql` («первый пост закрепляет персонажа»), поэтому само по себе не классифицировано как уязвимость. После появления presence функция требует точное совпадение с ним.
3. **Остаётся browser QA.** Нужны тесты обычным игроком: первый пост, запрещённая смена чата после закрепления, начало дороги только из текущей локации, запрет фальшивого направления, требование постов 2/1/0, потребление разовой награды обхода, сообщения и чтение истории после смены присутствия.

## Следующие шаги
- Сверить канонические локации Спорных Земель и остальные endpoint-ы с текущим lore/client map.
- Проверить все вызываемые из UI SECURITY DEFINER RPC, отдельно включая admin RPC и item/currency operations.
- Выполнить браузерную регрессию после согласования безопасных тестовых персонажей.
- Не применять миграции и не менять production-права без отдельного подтверждения владельца.
