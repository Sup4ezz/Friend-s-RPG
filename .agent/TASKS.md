# LORGUS — очередь автономной разработки

## P0 — безопасность и целостность RP
- [ ] Аудит всех RP-действий на клиентские обходы ограничения физического присутствия.
- [ ] Перенести критические проверки RP-присутствия на серверную сторону.
- [ ] Проверить RLS для rp_presence и связанных RP-таблиц.
- [ ] Убедиться, что открытие карточки локации не создаёт присутствие.
- [ ] Убедиться, что запись в чат разрешена только для текущего физического пространства персонажа.

## P1 — путешествия
- [ ] Централизовать граф дорог и маршрутов.
- [ ] Проверить только канонические соединения.
- [ ] Разделить land/sea-маршруты в модели данных.
- [ ] Сделать состояние путешествия устойчивым к перезагрузке.
- [ ] Подготовить основу для длительности путешествия и событий на дороге.

## P1 — письма
- [ ] Аудировать lorgus_mail SQL и RLS.
- [ ] Убрать клиентскую иллюзию мгновенной доставки.
- [ ] Реализовать серверную обработку deliver_at / delivered_at.
- [ ] Проверить права чтения и отправки.
- [ ] Не допускать отправку письма самому себе.

## P1 — стабильность
- [ ] Найти и исправить очевидные async/await ошибки в RP и флуде.
- [ ] Проверить восстановление активного персонажа после перезагрузки.
- [ ] Проверить обработку отсутствующего или устаревшего rp_presence.
- [ ] Добавить минимальные проверки критических JS-функций.

## P2 — UI
- [ ] Завершить унификацию иконок без emoji/text-symbol UI.
- [ ] Проверить экраны мира, персонажа, локаций, писем и RP.
- [ ] Сохранять литературный dark-fantasy стиль LORGUS.
- [ ] Не превращать интерфейс в стандартный RPG HUD.

## P2 — качество кода
- [ ] Найти дублирование логики RP.
- [ ] Выделить единые функции проверки присутствия и маршрутов.
- [ ] Уменьшить количество прямых Supabase-запросов из UI-обработчиков.
- [ ] Добавить комментарии только там, где логика неочевидна.

## Правило очереди

После выполнения задачи агент отмечает её выполненной, обновляет .agent/STATE.md, проверяет следующую задачу и продолжает работу, пока не встретит блокер или действие, требующее подтверждения.
